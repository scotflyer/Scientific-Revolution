# 双平台打包

**配置日期：** 2026-10-18  
**准备版本：** 0.1.0（打包准备版本，未经正式发行验收）  
**工具：** Electron 38.8.6、electron-builder 26.15.3，版本由锁文件固定。

## 1. 构建入口

在 `desktop-app/` 中先运行 `npm ci --no-audit --no-fund`，随后在对应系统运行：

| 命令 | 执行环境 | 产物 |
| --- | --- | --- |
| `npm run package:windows` | Windows；当前开发机可执行 | `release/windows/win-unpacked/` 独立 x64 目录包 |
| `npm run package:mac` | 已选路线的云端 Mac | `release/mac/mac-universal/科学革命.app` 及通用 ZIP |
| `npm run prepare:publication` | 任一平台 | `release/publication/` 内容清单、启动说明草稿及版本信息 |

两个打包命令都会先执行 `build:desktop`（包含既有 TypeScript 检查），再生成独立应用和配套文件。读者电脑无需安装 Node.js、npm 或开发依赖。脚本限制运行系统，Mac 包必须在 Mac 上生成。

每个平台输出附带 `build-info.json`（工具版本、主机、签名状态与待验收标记）和 `SHA256SUMS.txt`。校验值用于传输核对，不证明发布者身份。重新打包会更新本平台输出；发布前只取本次生成的产物，避免混用历史版本。

## 2. 打包边界

- 配置为 `electron-builder.config.cjs`；构建源限定 `dist/desktop/` 中的主进程、preload、共享代码、界面资源与内置内容清单。
- 视频、设计源图、QA 记录、浏览器/Sites 产物及开发依赖不纳入应用；约 17.01 GiB 原视频保留在外部目录。
- `asar: false` 保留真实文件，符合当前 `realpath` 与 Range 文件流读取方式。读者需保留整个程序目录；内容清单变更仍受阶段 D 严格校验。
- Windows 禁用执行文件签名，保留应用版本与名称资源编辑；x64 主机复用已安装的固定版本 Electron，避免重复下载。
- Mac 使用 `identity: '-'` 的 ad hoc 签名，关闭 hardened runtime，明确禁用公证。打包器处理嵌套组件与最终通用包，无需发布者证书。
- 脚本清理继承的常规签名及公证环境变量，关闭证书自动发现，不上传发行物、不自动发布。
- 项目版本统一来自根 `package.json`，同步到准备后的应用及发行版本信息。
- 桌面输出使用 `dist/desktop/`，发行输出使用 `release/`；浏览器/Sites 入口与输出保持现有路径。

## 3. 云端 Mac 准备

使用 Node.js 22.12 以上环境并安装 Xcode 命令行工具。上传源码、锁文件、配置与界面资源；不上传 Windows 的 `node_modules/`、`dist/`、`release/`。在 Mac 上通过 `npm ci` 安装本机依赖，再运行 `package:mac`。

无需 Apple Developer Program、Developer ID、私钥或公证账号。构建工具及两架构 Electron 下载需要网络；阅读器运行使用本地内容。通用包与 ZIP 在 Mac 上生成；传输和解包须保留符号链接及执行权限。

`minimumSystemVersion: '12.0.0'` 只声明系统下限，不证明兼容性；仍需 macOS 12 与 Intel/Apple Silicon 各自的运行证据。当前未配置云端 CI 自动发布。

## 4. U 盘组装

```text
U盘根目录/
├── Windows/             # 复制 win-unpacked 内的全部文件
├── macOS/科学革命.app   # 在 Mac 上从通用 ZIP 解包，完整保留包结构
├── content.json         # 来自 release/publication/
├── 视频/                # 原六个文件夹及44个原视频，原名保留
├── 启动说明.html        # 来自 release/publication/，验收后定稿
└── 版本信息.json        # 来自 release/publication/
```

配套目录不是完整发行物，不自动复制视频或两个平台的应用。组装时不要把开发用 `启动桌面应用.cmd` 当作读者入口，不要只取 Windows 的 EXE；Mac 归档在 Mac 上解包与复制，避免 Windows 解包损失属性。

当前内容发现可从应用路径向上查找 U 盘根目录；如果 macOS 隔离或 App Translocation 导致自动发现失败，可通过已有原生文件夹选择入口选择出版物根目录，实际流程须验收。

## 5. 后续验收

打包成功只证明该主机构建产物完成。本轮不新增或运行功能测试；后续仍需首次启动及系统手动允许步骤、macOS 两架构与目标系统、实际 U 盘文件属性、内容发现、离线播放、拔插、字体、5.1 声道素材及跨重启记录验收。策略限制见[云端 Mac 发行方案](../云端Mac发行方案.md)。

云端实例、实体 U 盘及 Mac 目标机尚未落实；发行说明保持准备稿，正式交付状态保持待验收。

## 6. GitHub Actions

项目方指定仓库为 `scotflyer/Scientific-Revolution`；已配置根目录 `.github/workflows/package-desktop.yml`，手动触发。Actions → Build desktop packages → Run workflow 选择 mac、windows 或 both，默认 mac。运行完成后下载 Artifacts，内层 Mac ZIP 保留应用结构与权限；产物保留 14 天。工作流不随提交自动执行、不发布 Release；账户额度与费用由 GitHub 套餐决定。CI 构建不上传原视频，不运行功能测试，仍需目标机与实体 U 盘验收。
